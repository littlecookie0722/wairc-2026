# WAIRC-2026 v0.9.0

This release completes receiver-specific synthetic robustness coverage without
changing the competition data or submission contracts.

## Highlights

- The controlled `robustness-small` profile now covers nine conditions,
  including dedicated `node1-missing` and `node2-missing` checks alongside the
  existing baseline, noise, node-0, frequency-offset, timing-offset,
  low-gain, and combined-stress conditions.
- The repository-authored `benchmark-fixture-v1` parameter manifest records
  all nine controls and pins the expected deterministic report signature. It
  contains no generated IQ, model outputs, external recordings, or private
  labels.

## Compatibility

The existing `cpu-smoke` profile and seven prior `robustness-small` conditions
remain unchanged. This release does not intentionally change the 0..8 label
mapping, interleaved IQ parsing, missing-node semantics, `stft-v1`, training,
inference, checkpoints, or submission serialization. The new conditions are
synthetic-only inputs for reproducibility and do not claim real-data
robustness or competition performance.

## Verification

The release candidate is required to pass the 157-test suite, data-free smoke
test, CPU compatibility probe, Ruff, bytecode compilation, both benchmark
profiles, source and wheel builds, source-distribution fixture checks,
isolated-wheel checks, and the GitHub Actions Python 3.10/3.11/3.12 matrix.

Synthetic metrics and fixture signatures are functional checks on generated
data only. They are not real-data benchmarks, competition scores, or adoption
claims. GPU training and full-data inference remain manual checks because
competition data and trained models are not distributed with the project.

## External assets

Competition data, trained checkpoints, generated caches, and private test
labels are not included. Users must obtain restricted assets through their
original channel and follow the applicable terms. Dependencies retain their
own licenses.
